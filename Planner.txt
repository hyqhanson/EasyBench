重新整理后的架构
1. 目标驱动入口层
输入参数应当包含：

--benchmark-type：integration / matching / clustering / annotation / deconvolution / trajectory / cell-type-prediction 等
--domain（可选）：singlecell / spatial / genomics / proteomics
--dataset / --paper / --doi / --query
这个层的工作是：

将 benchmark 类型映射到“所需数据类型、候选数据源、常见指标”
生成任务计划：benchmark_type -> search strategy -> metrics set
2. 数据收集层
Agent 根据 benchmark 类型自动收集数据：

integration：寻找多批次、多样本的单细胞数据集
matching：寻找对照/配对数据集、跨平台数据
clustering：寻找带标注的单细胞数据
annotation：寻找拥有已知细胞类型标签的 dataset
数据来源可以包括：

GEO/SRA/ArrayExpress
cellxgene
Figshare/Zenodo
文献附录中的下载链接
3. 文献收集与解析层
Agent 不是盲搜，而是“目标相关文献收集”：

根据 benchmark 类型检索关键论文
从论文中提取：
数据集 ID
方法/步骤
使用的代码仓库
评价指标
软件环境与版本
这一步应当产生一个“复现计划结构化文档”。

4. 环境与复现执行层
这一步是你的重点：

自动设置环境
conda / mamba 环境
或 Docker
自动获取论文中关联 GitHub
尝试运行论文方法
记录运行过程：
命令
依赖版本
随机种子
失败/成功原因
如果不能完全自动，还要输出“人工介入点”。

5. benchmark 阶段
根据 benchmark 类型进入评估：

使用已有 benchmark 标准
先运行“目标 benchmark 的基础指标”
再让 agent 生成候选新指标
最终形成“多维度评分矩阵”
输出内容应包括：

指标结果表
结果可视化

你的设计应该怎么改进
1. 把 benchmark 类型作为“第一层语义”
不要把它当成可选参数，而应当是主入口：

benchmark_type 决定数据收集策略
benchmark_type 决定指标集合
benchmark_type 决定检索优先级
2. 先做“目标-数据-文献”三段式
这个顺序最稳：

目标 -> 数据
目标 -> 文献
文献 -> 复现计划
3. 保留“手动审查点”
自动收集和自动环境搭建都很难做到 100% 成功。
设计时就该保留：

“数据源确认”
“代码仓库确认”
“复现结果确认”
4. 将 benchmark 设计成“可扩展类别”
建议先定义一个小的 benchmark 目录，例如：

integration
batch correction
modality alignment
matching
cell matching
sample matching
clustering
cluster accuracy
marker consistency
annotation
cell type prediction
deconvolution
cell fraction estimation
每个类别都定义：

典型数据类型
常见数据源
基础评价指标
5. 让 agent 先做“结构化任务生成”
即不是直接“让 LLM 去做一切”，而是：

用模板生成“任务计划”
让 agent按计划执行
记录“执行结果 + 差异”
